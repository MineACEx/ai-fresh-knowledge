# Claude Fable 5.2

> **一句话结论**：**一句命令**就能生成完整的 3D 游戏，12 个关卡、带射击玩法，全部代码产物只有 **1.4MB**。

## 时间线

| 日期 | 事件 |
|---|---|
| 2026-11-17 | ASCII.jp / Gigazine 同日报道该演示，社区引爆 |
| 2026-11-17 | "一夜之间做出 12 关动作游戏"的案例被多家媒体转载 |
| 后续 | GitHub 出现 `awesome-fable-5-2` 等社区资料库 |

## 关键事实

- **能力**：单个提示词 → 完整可玩 3D 游戏
- **规模**：**12 关**动作游戏；另有"完整 3D 射击游戏、画面表现力强"的案例
- **产物体积**：**1.4MB**（纯代码，无预置美术资源）
- **形态**：全部由代码生成，不依赖外部素材包
- **社区反馈**："完全按照指令一次成型"（gigazine 实测）

## 为什么重要

1.4MB 生成一个 3D 游戏，说明**它没有塞美术资源，而是用代码画出一切**——几何体、材质、光照、动画全靠程序生成。这跟"生成一堆贴图再拼装"是两条路。

对开发者来说，真正的意义在于**代码密度**：能在一次生成里维持 12 个关卡的一致架构，说明它有长程结构保持能力，不是只写能跑的片段。

## 评价

**优点**：产物体积极小说明代码质量高、无冗余；12 关的架构一致性是最难的部分，能做到说明规划能力强。

**问题**：演示归演示——**生成的游戏好不好玩是另一回事**。代码能跑通、能做 12 关，不等于关卡设计有趣、手感好、没有逻辑 bug。

**本喵的看法**：这是"技术奇观"级别的演示，但媒体标题的"恐怖"多半是营销。真正值得记的是 **1.4MB** 这个数字——它证明了程序化生成路线的可行性，而不是证明 AI 会做游戏设计。

## 容易搞错的地方

- ❌ 误解"一句话做出商业级游戏" → ✅ 是**演示/原型级**，不代表可直接发行
- ❌ 误解"1.4MB 是因为压缩" → ✅ 是因为**纯代码程序化生成，没有贴图音频资源**
- ❌ 误解"Fable 5.2 = Claude 的官方型号名" → ✅ 需按官方发布口径确认命名，社区传播名可能不同于 API 模型 ID
