# 高通主动下场 PC 转译

> **一句话结论**：高通不再让 Winlator/Box64 这类第三方折腾，**自己开发官方驱动 + 在骁龙上测试原生 DirectX 12**——PC 游戏上手机这件事，从社区自发变成芯片厂战略。

## 时间线

| 日期 | 事件 |
|---|---|
| 2026 | 报道称高通正在**为 Android 上的 PC 游戏开发官方驱动** |
| 2026 | 高通在骁龙平台**测试原生 DirectX 12 支持** |
| 同期 | 媒体："高通可能计划大幅强化 Android 上的 PC 游戏模拟" |
| 同期 | "手机游戏黄金时代即将到来？" |

## 关键事实

- **动作一**：高通开发**官方驱动**（此前这条路完全依赖社区 Adreno 驱动/自定义驱动）
- **动作二**：在骁龙平台测试**原生 DirectX 12**
- **意义**：从"模拟器自己想办法"→"芯片厂提供底层支持"
- **背景**：此前 PC 游戏在 Android 上主要靠 Winlator + Box64/Wine 等转译层，性能与兼容性都受限

## 为什么重要

**这是转译链路的责任重新分配。**

以前：游戏 → DX → 转译层（Wine/Box64）→ OpenGL/Vulkan → 驱动 → GPU
现在高通要做：游戏 → **DX12 原生** → 驱动 → GPU，砍掉中间层

原生 DX12 支持意味着**巨大的驱动工作量**——DX12 是低层 API，需要自己做命令缓冲、描述符堆、内存管理。高通愿意做，说明它认为**移动端跑 PC 3A 游戏**是下一阶段的卖点。

对开发者的实际影响：如果官方驱动开放，模拟器作者可以基于官方接口做，稳定性和性能都会显著提升；但同时也意味着**高通会掌握这条链路的话语权**。

## 评价

**优点**：芯片厂下场做驱动，是整个生态最大的利好——驱动质量直接决定能不能跑、跑多快。

**问题**：**DX12 原生支持的技术难度极高**，而且游戏厂商不会为手机重写，兼容性还是要靠转译兜底。另外这本质是**给游戏手机/游戏平板找卖点**，普通手机跑 3A 的功耗和散热仍是死结。

**本喵的看法**：高通这个动作说明它意识到**手机性能过剩了**——日常使用根本用不满旗舰 SoC，必须找一个能吃性能的场景。PC 游戏转译就是那个场景。

但真正的问题是：**手机上玩 3A 游戏的体验到底成不成立**？屏幕小、散热差、没有键鼠（虽然可以外接）。这个需求可能没高通想的那么大。

## 容易搞错的地方

- ❌ 误解"原生 DX12 = 游戏能直接装到手机跑" → ✅ 仍需**转译/兼容层**处理 x86 指令集差异（DX12 只是图形 API 层）
- ❌ 误解"这是模拟器厂商在做" → ✅ 是**高通自己在做驱动和 API 支持**
- ❌ 误解"已经可用了" → ✅ 报道口径是**开发/测试阶段**
